## 数据兼容原则

只读审计确认：生产库已有 461 条迁移、25 个未删除用户、29 把未删除 Key、20 个飞书身份、4 个分组，当前没有订阅。审计不导出用户邮箱、凭据或完整 Key。

原版有 305 个 SQL 迁移，双方共有 297 个同名文件。共同文件只有 `250_openai_cache_write_ttl.sql` 存在内容差异，差异仅为末尾空行，迁移执行器先 TrimSpace 再计算 checksum，因此实际校验值相同，无需放宽校验。

迁移必须满足：

- 保留用户、余额、Key 字符串及归属、分组、账号凭据、飞书身份、会话和测试历史。
- 不在生产库执行迁移演练、不清空数据库、不重建用户、不发真实邮件或测试 Key。
- 旧扩展退役不等于删除旧表；历史 SQL 和校验信息必须可追溯，新安装不再创建无关扩展。
- 对旧版多分组 Key、影子账号、VIP 垫付、定时质量联动等差异，先统计实际使用，再明确兼容处理；不能靠忽略字段悄悄改变权限、余额或调度。
- 在 GitHub Actions 的临时 PostgreSQL 中覆盖全新安装与旧库升级演练，验证核心记录与权限边界。

## Actions 与更新流程

旧版 reusable CI 含数百个历史回归任务。本次去掉旧分支的历史矩阵，保留原版当前检查，并补充 Pro 功能、迁移兼容、前端构建和安全检查。减少的是已退出维护范围的旧检查，不省略当前源码的验证。

迁移候选分支不允许发布生产镜像或部署。全部构建、测试和代码生成都在 GitHub Actions；本机只进行源码处理、格式化、静态检查和只读审计。

批准上线后，自动更新的来源固定为 `Wei-Shaw/sub2api/main`。更新先进入候选分支，核对 Pro 保护清单和固定 SHA 的 CI，成功后再推广与部署。不能把状态未知、取消或超时当作检查成功。

## 审阅时必须提供

1. 实际移植文件和退役入口清单。
2. 全新安装、旧库升级、主题、登录、飞书、Key、账号池、手动/定时智商检测的 Actions 结果。
3. 数据及既有权限差异的检查结果、尚未解决的限制。
4. 待部署的确切提交和可回退源码位置；用户确认前保持生产服务与正式更新配置不变。

## 权限语义核对

只读核对生产配置：29 把 Key 均已有官方 `group_id`，旧 `api_key_groups` 无关联；每 Key 自定义并发、模型映射、上下文限制均为零；账号分组模型限制、用户分组模型禁用均为零；自动垫付配置与账本为空。因此不需要为现存数据继续引入旧版扩展域模型。

官方每把 Key 绑定一个分组；发放接口保留 `group_ids` 数组作为响应兼容字段，但长度固定为一，并发继承用户。升级增加防护：遇到多分组或冲突关联、正在使用的退役模型限制、Key 并发/模型/推理/上下文限制、启用的自动垫付规则时停止迁移并要求人工复核，不静默放行。

账号池的倍率继续使用官方实现；余额读取保留为独立的只读定制，使用 `/v1/usage`、URL/代理校验、禁重定向、响应大小限制、过期标记和并发上限，不能把倍率当余额。手动记录继续兼容旧浏览器存储格式，保留最近8次并限制长输出长度；普通用户不保存本机记录。智商检测保留糖果题、鹈鹕动画题、自定义题、推理档位、并行执行、状态探针及定时历史；状态探针属于经验判断，不能证明模型身份或科学智商分数，不自动处罚或恢复账号。
